# 蓝光与播放列表

> [English](Blu-ray-and-Playlists) · 中文

## 蓝光光盘

一个 `.iso` 文件或一个 BDMV 目录是**一个播放列表条目** —— 一条 mpv 流。光盘的标题是该流的
**edition**，不是彼此独立的条目：

- 右键 → **Title** 将它们列为 `Title 2 · 1:48:26`（序号与时长）；光盘带菜单时还会多出一条合成的
  **Disc menu** 条目。
- **Boot into disc menu**（Preferences → Disc，默认开启）决定打开光盘时是进入光盘自己的菜单，还是
  直接开始最长的标题。
- 选择标题或章节不会重新加载文件：mpv 在同一条流内跳转，滤镜链与 AI 引擎因此保持热态。
- 章节在右键 → **Chapter** 中，读取自正在播放的那个标题。
- AACS 加密的光盘可以被枚举，但没有密钥无法解密；播放器会如实报告 libbluray 的说法，而不是静默失败。
- 挂载后的光盘目录和普通 `.iso` 文件都可以用；镜像不必挂载。
- ⚠ 从 0.7.x 升级：每个标题各存一条 `bd://mpls/...` 的播放列表不再可用（0.8.0 跟随 mpv 0.42，
  一张光盘就是一个条目）。重新打开 ISO，标题就会回到 **Title** 面板。
- 手写的 `.m3u` 可以按**文件路径**列出光盘。本地播放列表里的 `bd://mpls/...` URL 会被 mpv 拒绝
  （来源检查），所以不要手写这类 URL。

**不支持 3D 蓝光（MVC）** —— 那需要软件解码两个相互依赖的视图，并且会改动整条 GPU 管线。请先离线把
光盘转成全宽 SBS，再用「3D glasses · side by side · full」播放。转换脚本是公开的：
<https://gist.github.com/zhangmq/cb457cb5263f2101b7adf36d81b46e31>。

## 光盘菜单

菜单显示期间控制栏隐藏，输入转发给光盘：

| 输入 | 操作 |
|---|---|
| 方向键 · `Enter` · `Esc` | 导航 · 激活 · 返回（mpv 的 `discnav`） |
| 鼠标移动 / 点击 | 由光盘自身映射到按钮上 |
| `Ctrl+M` | 根菜单 |
| `Ctrl+Shift+M` | 弹出菜单 |

菜单画面是光盘自带的图形，由 mpv 合成进视频帧，因此会出现在截图中，也走正常的渲染路径。

## BD-J 光盘：哪些能用，哪些不能

BD-J 光盘用 **Java applet** 运行菜单，而不是 HDMV 字节码。为此 libbluray 需要 Java VM 以及它自己的
BD-J jar（`libbluray-j2se-<version>.jar`）；播放器不自带。缺少任一项时，mpv 会记录一条警告，并
**不带菜单**地播放光盘 —— 其标题仍会列在 Title 面板里。

在 applet 确实能运行的情况下，有三条限制值得了解。它们全部是上游 mpv 的行为，不是播放器的 bug：

- **Title 面板可能一直停在 `Disc menu`。** Java 菜单通常从它自己的一份播放列表副本开始播放 ——
  例如光盘的 `00001.mpls` 旁边的 `01001.mpls`，除播放列表编号外完全相同 —— 而这些副本不在光盘索引的
  标题列表里。于是 libbluray 没有标题可以报告，mpv 便有意把 edition 指向合成的 `Disc menu` 条目
  （「光盘正在播放标题列表里没有的内容」）。画面是正常的；只是当前标题的名称未知。章节仍然可用，因为
  它们来自实际正在播放的那份播放列表。
- **菜单调用可能被拒绝。** 光盘可以屏蔽「menu call」这项用户操作；此时 `Ctrl+M` 与 Title →
  `Disc menu` 一行完全不起作用。有些光盘连弹出菜单也屏蔽，因此在重新打开光盘之前可能无法回到根菜单。
- **流程由 applet 决定。** 章节选择、正片起播与「返回菜单」都在 Java 菜单内部执行；播放器只转发
  按键/鼠标并绘制叠加层。光盘没有提供的功能，无法从播放器触及。

如果某张光盘的菜单不可用，把 Preferences → Disc → *Boot into disc menu* 关掉：光盘随后会直接开始最长
的标题，Title 面板仍可跳到任意标题（mpv 的 `bd_select_title`，光盘无法屏蔽）。

## 播放列表持久化

播放列表存为标准 **m3u8** 文件：

```
~/.local/share/vsr-player/last-playlist.m3u8
```

```m3u
#EXTM3U
#VSR-CURRENT:1
#EXTINF:-1,disc.iso
/home/user/disc.iso
#EXTINF:-1,film.mkv
/home/user/films/film.mkv
```

- 播放列表每次变化时，该文件都会原子重写（`QSaveFile`）。
- `#EXTINF` 携带条目名，名字正是靠它跨重启保留：播放通过 mpv 自己的播放列表解析器（`loadlist`）
  恢复，因此条目名来自 m3u 文件，与其他任何播放列表完全一样 —— 播放器自己不再维护名字表。
- 一张光盘就是一个条目，因此不会按标题存任何东西：它的标题随光盘本身一起回来。
- `#VSR-CURRENT` 是自定义注释（mpv 会跳过），保存所选条目的索引，使无参数重启时能高亮正确的那一行。

无参数启动会恢复这份列表，**但不载入任何媒体** —— 在按下播放之前不解码、不做引擎运算、不占用显存。

`~/.config/vsr-player/vsr-player.conf` 里较旧的 `playlist` / `playlistCurrent` 键，只在 m3u8 文件
不存在时作为回退读取（从旧版本升级而来）；它们不再被写入。

## 移除与删除条目

| 操作 | 按键 | 菜单 | 是否动磁盘 |
|---|---|---|---|
| 从播放列表移除当前条目 | `Delete` | Remove from playlist | 否 |
| 删除当前文件 | `Shift+Delete` | Delete file | 是 —— 移到回收站（`gio trash`） |

两者之后的推进完全遵循 mpv 的 `playlist-remove`：下一个条目成为当前条目（并保持暂停状态），或者在
没有剩余条目时播放器转入 idle。

只有真实、可写的本地文件才提供删除 —— URL 和流没有文件可删。`gio trash` 会拒绝 tmpfs 上的文件；
这种情况下播放列表保持不动，并记录一条错误。
